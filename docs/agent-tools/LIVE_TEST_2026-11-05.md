# Agent tools: live test on Specula, 2026-11-05

This log records a live test of the seven agent tools in [AGENTS.md](../../AGENTS.md) ("Agent tools"). Each tool
was driven the way an agent drives it, on this repository, on Windows. It is the evidence behind the "how to use
these" guide at the end.

**Update, same day:** every bug below was fixed in the next releases and re-verified on this repository. See
[Re-verification (fixed releases)](#re-verification-fixed-releases) at the end, which replaces the workarounds in the
guide.

- **Repository:** branch `claude/agent-tools-setup` at `420c5c1`: about 317k lines of Rust, 529 `.rs` files, 1625
  tracked files and 792 commits.
- **Machine:** Windows 11, Git Bash and PowerShell, Rust stable GNU, Python 3.13. Builds used `CARGO_TARGET_DIR`
  folders under `C:\tmp\specula-agenttools\`, all deleted afterwards. `RUSTFLAGS` was never set.
- **Method:** a throwaway Python harness spoke newline JSON-RPC over stdio to each server (`initialize`,
  `notifications/initialized`, `tools/list`, `tools/call`), with the Specula root as the working directory.
  - "ms" is the round trip of one request, measured in the harness. "B" is the size of the reply line in bytes.
  - "Cold" is the first run on an empty store; "warm" is the next.
- **Versions:** Chisel 0.20.0, Stele 2.2.0, wikifier 5.2.0, Trammel 4.2.0, Relatum 1.3.0, CoordinationHub 1.1.0,
  Probatio 0.7.0.

  - Test edges are 86 MB of the file. Name-matched call edges average about 194 per test.
  - Sharding would not help: `crates/specula` alone holds most of the edges.
- **Are the suggestions right?** Mostly. `diff_impact` named exactly the two tests that call `yaw_difference`
  directly. It does not follow calls through `solve()`, so other `solve` tests that reach the function were not
  named. Running `cargo test -p specula-locus` (0.1 s of tests) is still the sensible action.
- **Issues, on a scoped snapshot.**

  - `chisel capture --command "cargo test -p specula-locus" < out.txt` took **0.10 s**. It printed one line and

## Windows notes

- Every server started in 2-10 ms. Trammel's and Probatio's temp work goes to `%TEMP%` (C:); keep
  `CARGO_TARGET_DIR` on C: too.
- **Line endings:**
  - Git has `core.autocrlf=true` system-wide, but Specula's working files are LF.
  - Editing with `sed` gave only the usual "LF will be replaced by CRLF" warning, and diffs stayed one line.
  - Probatio's span patcher handles CRLF either way.
- **Path separators:** Stele returns `\`-separated paths. Chisel's issue excerpts keep the panic's `crates\...`
  path. All other tools use `/`. Stele's `path_prefix` accepts both.
- **Probatio** runs suites under Git for Windows' `sh`. Plain `cargo test` worked; so did `;`, `$?` and `>>` in a
  suite command.
- **Python harness output:** printing the reply text to a cp1252 console turned "…" into a replacement character.
  The bytes on the wire were valid UTF-8. Set `PYTHONIOENCODING=utf-8` for harnesses.
- **No firewall prompts:** nothing bound a port. `coordinationhub serve-sse` and `chisel serve` weren't used.

## Bugs and exact repros

Each repro is on Specula `420c5c1`, in Git Bash, from the repository root, unless it says otherwise.

### B1 Chisel cannot read its own snapshot over 32 MiB

```sh
chisel analyze .              # writes .chisel/store: 98,925,899 bytes (test_edges alone about 86 MB)
chisel stats --json           # Error: json exceeds 32MiB   (exit 1)
chisel serve-mcp < /dev/null  # exits at startup with the same line, so the MCP client sees a failed server
```

The cause is `src/json.rs:216`: `parse` rejects any input over `32 * 1024 * 1024`, but the snapshot writer has no
cap. The 461,698 name-matched test edges make up most of the size.

### B2 Chisel capture and the hooks fail silently when the snapshot cannot load

With the store from B1 in place:

```sh
CARGO_TARGET_DIR=C:/tmp/x cargo test -p specula-locus > out.txt 2>&1   # with one test broken
chisel capture --command "cargo test -p specula-locus" < out.txt; echo $?   # no output, 0; store not written
chisel issues --brief; echo $?                                                 # no output, 0
chisel issues --json                                                           # Error: json exceeds 32MiB (exit 1)
```

### B3 Chisel names an unchanged function as a changed suspect

Use a scoped snapshot (`CHISEL_STORAGE_DIR=<dir> chisel analyze crates/specula-locus`), then:
1. `chisel run -- cargo test -p specula-locus`, all green.
2. In `crates/specula-locus/src/geom.rs`, change `yaw_toward` to return `dmath::atan2(dx, dz).to_degrees() + 1.0`.
3. `chisel run -- cargo test -p specula-locus`.

Then `chisel issue I2` for `solve.rs:against_a_wall_faces_away_and_touches` lists
`{"unit": "aligned", "reason": "+1 -1 since last pass (420c5c1), uncommitted; the test calls aligned, new"}`.
`aligned` is unchanged. The changed function, `yaw_toward` (reached through `solve()`), is not listed.

### B10 Probatio mutate_diff on a workspace member reports every mutant unviable

1. In `crates/specula-locus/src/geom.rs` line 34, change `if d < 0.0 {` to `if d < 0.0 && d > -720.0 {`.
2. Over MCP, call `mutate_diff {"package": "D:\\Coding Projects\\Specula\\crates\\specula-locus"}`.

The reply is "3 mutants ... 3 did not build" and `next`: "No survivor: every mutant on the changed lines was
caught". The baseline was green.
- With a suite command that logs `pwd`, each mutant ran in `%TEMP%\probatio-<id>-0`.
- That folder's root held the crate's own `Cargo.toml`, and cargo failed with `failed to parse manifest ... error
  inheriting edition from workspace root manifest ... failed to find a workspace root`.
- So the mutant tree is built from the package folder, not the repository. `overlay_working_tree(repo, dest)` and
  `prune_extras` seem to receive the package path.

Two more problems compound it:
- `decide.rs::looks_unviable` treats cargo's `error:` line as a build failure. That's right here, but it also means
  a misbuilt tree reads as "did not build" rather than as an error.
- The `next` text claims every mutant was caught.

Workaround: `{"package": "<repo root>", "suiteCommand": "cargo test -p specula-locus"}` scores correctly.

### B12 CoordinationHub deregister does not release the coordinator lease

```text
register_agent {"agent_id":"lease-probe"}
acquire_coordinator_lease {"agent_id":"lease-probe","ttl":300}   -> acquired, lease_name COORDINATOR_LEADER
deregister_agent {"agent_id":"lease-probe"}                       -> "lease_released": false
manage_leases {"action":"get"}                                    -> leader still lease-probe
```

The cause is `src/act_identity.rs:403`: `release_lease` only matches `lease_name == "coordinator"`, but the lease is
stored as `COORDINATOR_LEADER`. Separately, `manage_leases get` still returned `lead`'s lease (`ttl` 60) about 300 s
after its `expires_at`. Acquiring after expiry did succeed.

(B8 is not used: the unignored wikifier files were a setup gap, fixed in `.gitignore`, not a bug.)
